## 0. 一句话

**你是那个事件里的一个人。** 外部事件按历史的时间表一件件到来，你只能在你这个位置上、用你手上的资源做出回应；每一步都有代价，没有人告诉你历史原本是怎么走的——走完这一段，你走出的是属于你的一条路。

## 1. 背景与问题

「争鸣」前两个模块解决了「观点的沉淀（树）」与「观点的交锋（间）」，但议题始终是**抽象问题**（该不该 X）。而事件类内容天然具备辩论议题没有的东西：

1. **具体性与代入感**。事件有当事人、有时间线、有约束条件——但"换你会怎么选"只能靠**你真的在那个位置上**才能兑现。
2. **真实的时间压力**。真实决策不是"选一次就结束"，而是外部事件一件件砸过来，你在信息不全、资源有限、时间不够的情况下连续应对。
3. **代价的不可撤销**。抽象辩论永远可以嘴硬；角色扮演里你选了就是选了，代价跟着你走到最后。

但如果直接做「事件模拟器」，会踩四个坑：模拟与事实混在一起变成历史虚无；玩家站在上帝视角评判当事人；把他人真实的苦难做成娱乐化重演；让模型即兴编造事实，把推演变成不可追责的虚构。

v0.5 用**做游戏**来正面回应前两个坑：

- 把玩家放进局内 → 你不再能俯视当事人，因为你和他在同一个位置、受同一组约束；
- 让你只知道角色该知道的 → 信息不对称使"他当时应该……"这句话在机制上说不出口。

## 2. 目标与非目标

**目标**

- G1 角色扮演：开局从事件中的若干**角色位**中选一个，以该位置的视角、资源与信息量参与事件。
- G2 幕推进：外部事件按历史时间表到来，你以角色身份做出决定，看后果与代价。
- G3 代价与关系：每一步记账（时间 / 钱 / 关系 / 健康 / 机会）并改变他人对你的态度；**无分数、无成败**。
- G4 自动收束：达到结束条件后自动进入结局，生成属于你这条路的结局叙述。
- G5 沉浸式信息隔离：推演期间**不展示也不生成**历史原作；原作只在终局以**可选**方式揭示。
- G6 Host 追问：Agent 只在决策假设层面追问，不裁判选择。

**非目标（本期不做）**

- **预测未来**（面向已发生事件，不做走势预测）
- **扮演真实当事人本人**（见 §3.4：角色位必须化名、改编；不做"重演真人真实选择"）
- **胜负与评分**（永不做——用代价账本替代，三个模块共用同一条产品底线）
- 真实多人同局（本期是单人扮演 + 结束后对比；共局博弈另案）
- 运行时事实检索（原作离线入库、人工审核）
- 分支穷尽与"最优解"（不枚举、不判定）

## 3. 概念模型

### 3.1 三层结构

```
Event（一个改编自真实事件的可扮演场景）
 ├─ header      场景头：背景陈述 + 年代 + 改编声明 + 准入审核记录
 ├─ positions   可扮演的角色位（≥2 个，玩家开局选一个）
 ├─ acts        外部事件节拍（**锁定**）：按历史的时间表到来，玩家无法阻止
 ├─ endingCondition  收束条件（本期：到达第 N 幕即自动收束）
 └─ canon?      原作轨迹（历史上实际发生的事）
                 —— 推演期间**不展示、不注入模型**；仅用于终局可选揭示与准入可核验性
```

**`acts` 是锁定的，`canon` 是隐藏的**——这是本版一条重要的分工：

- `acts` 给出**外部压力**（"苏州的电话再次打来""合并文件下发"）。它不因玩家的选择改变，这是"历史收束力"的轻量实现，也保证游戏不会无限漂移。
- `canon` 给出**现实依据**（这批 `acts` 不是编的）。它同时是 §4 F5 的揭示素材与准入审核的证据，但**不参与生成**——所以沉浸式反而让"调用隔离"成为天然属性（见 §3.3）。

**`realTimeline` 的定位变化（对 v0.4 的降级说明）**：在 v0.4 里真实发展线是"终局对照的硬锚点"，是产品的差异化卖点；本版把它降到**骨架来源 + 可选揭示 + 审核证据**。这是一次有意识的取舍：用"与现实对照"换"沉浸感"。若终局的可选揭示也去掉，`canon` 就只剩骨架与审核两个用途。

### 3.2 角色位（Position）：用信息不对称消解上帝视角

开局玩家从若干角色位中选一个。每个角色位定义：

```ts
interface Position {
  id: string;
  name: string;              // 化名后的称呼，如「县中的物理老师」「教务主任」
  stake: string;             // 你在乎什么：孩子 / 职位 / 收入 / 面子 / 团队
  visible: string;           // 你能看到的信息范围（关键字段）
  resources: string;         // 可动用的资源：积蓄 / 人脉 / 时间 / 编制
  canDo: string[];           // 你能发起哪类动作
  relations: { to: string; attitude: number }[];  // 与其他角色的初始态度
}
```

**这是本版最重要的机制**：`visible` 限制了你看到的信息，`resources` 限制了你能做的事，`relations` 限制了你说得动谁。于是——

- 你不可能全知，所以"他当时应该……"在机制上说不出口；
- 换一个角色位，同一事件是完全不同的游戏（信息、资源、能动性全变）；
- **可重复游玩性来自角色位，而不是来自分支穷尽**。

示例角色位（老陈事件）：`老陈本人`（在乎孩子与职业前途，能动性最高，信息最全）／`妻子`（在乎家庭完整与孩子成绩，资源少但有关键否决权）／`教务主任`（在乎教研组稳定，信息面不同，能影响老陈的编制安排）。

### 3.3 沉浸式信息隔离

v0.4 要花大力气"藏住真实走向"；本版的隔离更简单也更彻底：

1. **不注入**：`actAdvance` / `replayEnding` 的入参中**不含** `canon`。沉浸式下模型本来就不需要知道原作，所以调用隔离是**天然属性**而非额外防护。
2. **不展示**：推演期间界面不出现任何历史原作内容；`canon` 只在 §4 F5 的终局可选揭示中被请求（`replayCanon`）。
3. **输出兜底校验**：仍保留关键词黑名单（真实人物真名、机构名、原作结局关键词）与共享禁用词表——模型可能从背景知识里"猜到"真实结局并写进文案，这一层不能省。
4. **史实 / 架空标识**：玩家走过的路径在一切分享、导出的场合都必须标注「**架空推演**」；终局揭示的原作标注「**史实**」。两者永不出现在同一张卡里。
5. **改编声明**：场景卡固定显示「改编自真实事件，人物机构已模糊化，**你在扮演的是虚构角色，不代表当事人的真实选择**」——本版比 v0.4 更需要这句话，因为玩家是在替一个位置上的人做决定。

### 3.4 事件库准入底线

- 只收录**公共讨论充分**的事件（知乎已有问题/高热度讨论），不收录可识别个人的私事。
- 涉及灾难、伤亡的事件不入库（扮演 ≠ 消费苦难）。
- 改编规则：人物化名、机构模糊、时间粒度到月。
- **（本版新增，最重要）不扮演可识别的真实个人**：角色位一律是**改编后的虚构位置**，禁止以"你就是某某本人"招揽玩家，也禁止把玩家的选择呈现为当事人的真实选择。
- `canon` 必须有可核验来源并记录审核时间；来源失效时下架事件，而非静默替换。
- 角色位 ≥2 个且各自的 `visible` / `resources` 确有差异——只有一个可玩位置的场景不算合格事件。

## 4. 功能需求

### F1 角色位选择（P0）

- 进入事件后先显示场景头（背景 + 改编声明），然后让玩家选一个角色位。
- 每个角色位显示：称呼、你在乎什么（`stake`）、你能做什么与不能做什么（`canDo` / `resources` 的通俗表述）、初始关系概览。
- **不显示**该角色位在原作中的命运，或任何原作信息——选角色不是在做"选一个结局"，而是在选一个处境。

### F2 幕推进与决定（P0）

- 每幕：**外部事件到达**（锁定文案，不可协商）→ 呈现你角色视角下的处境（含 `visible` 范围内的信息）→ 给出 2-3 个可选动作 → 你做决定 → 请求 `actAdvance` → 生成后果、关系变化、记账变化 → 进入下一幕。
- 动作卡显示：动作文案 + **代价提示**（要花什么：钱/时间/人情）+ 你角色对它的**隐含假设**（`implicitAssumption`，供 F6 追问使用）。**代价提示不给结果预告**。
- 生成期间禁用其他动作并显示加载态；生成走**流式输出**（D4 已拍板）：处境与后果叙事边到边渲染，动作卡等完整结果过校验后才可交互；流中断显示「这一步暂时无法推进」+ 整幕重试，**不得用部分文本或静态模板冒充模型结果**。

### F3 代价账本与关系（P0）

- **账本**：时间 / 钱 / 关系 / 健康 / 机会，每幕结算增减，随时可查（这是替代"分数"的反馈系统）。
- **关系**：事件中其他角色对你的态度值（信任 ↔ 距离）。你的动作会改变它，态度又**反向限制**你之后的动作（"妻子已不信任你 → 你无法说服她一起搬"）。
- **无分数、无排名、无成败判定**。账本只陈述"你付出了什么、得到了什么"。

### F4 自动收束与结局（P0）

- 到达 `endingCondition`（本期为第 N 幕）后**自动结束**，不设"通关/失败"。
- 终局请求 `replayEnding` 生成结局叙述：必须与玩家实际走过的路径、账本、关系状态连贯。
- 结局卡呈现：你的角色位、你走过的关键决定、账本总账、关系终态、结局叙述——**不含任何优劣评价**。

### F5 原作揭示（可选，仅终局）

- 推演期间**绝不出现**。结局卡之后提供一个折叠入口「历史上实际发生了什么」，点击才请求 `replayCanon`。
- 内容：原作轨迹 + 知乎溯源摘要（≤200 字）+ 跳转原文，整块以灰底 + 「史实」角标呈现，与「架空推演」严格分开。
- **明确文案**：这不是"正确答案"，只是"现实中发生过的那一条"。不作对比评级、不打勾。

### F6 Host 追问（P0）

- 原料是**动作自带的 `implicitAssumption`**：每个动作在生成时带上"选它意味着你相信什么"。
- 幕间：在你做出决定后给一条**假设澄清式**追问（「你选这条路，隐含假设是孩子能适应新环境——这个假设的依据是什么？」），**不评判选择本身**。
- 终局：输出 2 条追问，指向你的**决策模式**（「你在三次决定里都选了风险更低的一边——这是你作为{角色位}的处境使然，还是你的风格？」）。

### F7 复盘与同路人对比（P1，本期降级）

- **只在结束后**展示（推演中展示会破坏沉浸感并引导从众）。
- 内容：同一幕里其他玩家怎么选、以及"与你同路的人在哪些幕和你分开"。
- 数据本期为静态演示；不做真实聚合。样本 < 50 显示「样本尚少」。

## 5. 关键流程

### P1 一次完整扮演

```
事件库选事件 → 场景头（含改编声明）→ 选角色位
  → 第 1 幕：外部事件到达 → 你的处境 → 2-3 个动作（带代价提示）→ 决定
  → actAdvance → 后果 + 关系变化 + 记账 → 第 2 幕 …… 循环
  → 到达收束条件 → 自动结束 → replayEnding → 结局卡（无评价）
  → （可选）展开「历史上实际发生了什么」
  → 结束后：同路人对比 / 分叉热力
```

### P2 换一个角色位重玩

```
同一事件换角色位 → visible / resources / relations 全变
  → 同一个外部事件节拍，完全不同的处境与可选动作
  → 走出另一条路（可玩性来自角色位，而非分支穷尽）
```

### P3 与其他模块的关系（仅用户动线，无系统联动）

```
争议地图 / 辩论树（发现议题与观点）→ 事件推演（把议题变成可独自扮演的处境）
  → 玩家带着体感自然回到社区讨论——但全程不跳转、不导出、不建机制入口
```

## 6. 反模式与边界

| 反模式 | 对策 |
|---|---|
| 玩家以上帝视角评判当事人 | **机制性消解**：`visible` 限制信息、`resources` 限制手段、`relations` 限制影响力——你不在能评判的位置上 |
| 扮演真人、替真人做决定 | 角色位一律改编为虚构位置；场景卡固定改编声明；明确"不代表当事人的真实选择" |
| 把玩家的选择当成当事人的真实选择传播 | 一切分享/导出内容强制标「架空推演」；史实仅在 F5 灰底区块出现 |
| 消费苦难 / 私事 | 准入五条底线（§3.4），人工审核 |
| 模型编造历史当背景 | `canon` 不参与生成；`acts` 锁定；关键词黑名单兜底 |
| 玩家被"最优解"思维绑架 | 无分数无成败；代价账本只陈述付出与得到；不提供对比评级 |
| 游戏无限漂移、节奏失控 | `acts` 锁定 + `endingCondition` 到时自动收束 |
| 后续生成与已发生后果矛盾 | 固化原则：已生成的后果作为锁定条件注入后续调用 |
| 生成失败时假装有结果 | 明确「暂时无法推进」+ 重试，禁止静态模板兜底 |
| 结束后统计引导从众 | 同路人数据只在结束后展示，且标注为演示数据 |

## 7. MVP 范围与验收

**本期交付**：F1 + F2 + F3 + F4 + F6（P0），F5 做可选揭示（带审核来源），F7 做静态演示版。

**验收清单**

- [ ] 同一事件至少有 2 个可玩角色位，且信息量/资源/可选动作确有差异
- [ ] 一次扮演可连续推进 ≥3 幕，每幕由外部事件到达触发，2-3 个动作带代价提示
- [ ] 推演期间界面与生成结果中**不出现任何原作信息**（含关键词黑名单断言通过）
- [ ] 账本与关系随决定变化，且关系反向限制后续可选动作
- [ ] 到达收束条件自动结束，结局叙述与走过的路径连贯，**无任何评分或优劣评价**
- [ ] 结局后可展开「历史上实际发生了什么」，带知乎溯源且标「史实」；玩家路径标「架空推演」
- [ ] Host 追问为假设澄清式，无评判词；超时显示「暂时无法推进」而非假结果

## 8. 原型说明

- `prototypes/event-replay-prototype.html`（静态数据版，26 项测试）：**只作视觉与壳体基线，不作语义基线**。
  2026-09-14 拍板（v0.6）：前端界面**沿用原型的视觉系统与三栏壳体**——顶栏 logo + crumb + 按钮组、
  三栏（左：事件卡 / 推演路径 / 图层说明；中：舞台；右：Host 追问 / 我的路径 / 本局数据 / 代价账本）、
  内缩分割线卡片、时间轴圆点、折叠层、终局遮罩对照表，配色取原型同一套 `--er-*` 变量。
- **原型中不予实现的旧语义元素**（与已作废决策逐条对应，实现时必须缺席）：
  | 原型元素 | 处置 | 依据 |
  |---|---|---|
  | 选项上的 `%` 占比 + 进度条 / 终局「多数人」列 | 不实现 | 无社群数据；不判输赢 |
  | 时间轴「↺ 从这里重走」 | 不实现 | 本版 no-rewind，代价不可撤销 |
  | 「把分歧点沉淀到辩论树」入口 | 不实现 | G6 已作废（与辩论树完全解耦） |
  | 预设四结局 A/B/C/D | 不实现 | 结局由 `replayEnding` 生成 |
  | 折叠式「真实历史中老陈做了什么」逐幕折页 | **改写** | 红线 3：推演期间不得出现原作；只在终局对照里、且玩家主动揭示后才进 DOM |
- 演示与截图须基于 `web/` 的 `?view=event`，**不要用原型 HTML**——原型里保留着已砍掉的开辩论入口，演示它会误导评审。
- 本版走 `web/` + `HostClient`（见 `event-replay-PLAN.md`），不新建第二套原型。
- 无 Host（服务端能力 5/6/7 未就绪）时，可用 dev-only 版式夹具 `web/visual-check.html?auto=play|ending`
  （脚本化 mock 客户端，**不进构建产物**）核对三栏版式与终局遮罩；夹具内容不得当作模型输出对外展示。
- 若要快速验证游戏性，优先做一个**单场景 + 单个角色位 + 两幕**的最小可玩切片，而不是先补齐事件库。

## 9. Host 契约能力

> 编号与 `IMPLEMENTATION-PATH.md` 卡 0-1 能力表一致（`alignConcepts` / `checkRestatement` 相继移除后两轮整体前移；本模块消费其中的 5/6/7）。

| # | 能力 | 签名 | 用途 |
|---|---|---|---|
| 5 | 幕推进 | `actAdvance(header, position, acts, actIndex, ledger, relations, history, chosenMoveId) → {outcome, nextScene:{month,text,visibleFacts}, moves:[{id,text,costHint,implicitAssumption,label}], relationDeltas[], ledgerDeltas[], atEnding}` | **核心**：按你的角色位与处境推进一幕 |
| 6 | 结局生成 | `replayEnding(position, history, ledger, relations) → {title, text}` | 终局叙述，与走过的路径连贯 |
| 7 | 原作揭示 | `replayCanon(eventId) → {canon:[{actIndex, month, development, sources[]}]}` | **仅终局可选揭示时调用**，推演期间不调用 |

**硬约束**

1. **能力 5/6 的入参中不得出现 `canon` / `realChoice` / 真实人物真名**——沉浸式下这是天然属性，但仍须写成单测断言（spy 捕获请求体）。
2. 能力 5 的 `moves` 数量必须为 2-3；超界即视为脏数据拒收。
3. 能力 5 的 `visibleFacts` 不得越出该角色位 `visible` 的范围（越界即拒收）。
4. 能力 6/7 的返回文本过**禁用词表**：`错误 | 谬误 | 偷换 | 输赢 | 对错 | 你错了 | 赢了`。
5. 能力 7 的 `sources[].url` 必须为可访问的 https 知乎链接，`reviewedAt` 必填。
6. 超时与错误沿用 `host-contract.md` 的统一错误结构。

## 10. 与底座的关系

- **本模块是自洽的单人体验**（2026-09-13 拍板）：不与辩论树 / 辩论间做任何跳转、议题导出或 schema 共享——推演数据的消费方只有玩家自己（终局揭示与复盘对比）。
- 与其他模块只共享两样东西：**Host 通道**（`zhengming-server/` 同一契约）与**产品红线**（不判输赢、追问权、禁用词表）。
- 事件推演对产品整体的贡献是**题材与情绪**：它把抽象议题落成具体处境，玩家带着这种体感自然流向其他模块——但这是**用户动线**，不是系统联动，不建任何机制上的入口。
