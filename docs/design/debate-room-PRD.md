# 辩论间 PRD（v0.7 · 选边制撮合）

版本 v0.7（选边制 · 有限质询） · 2026-09-14 · 隶属「争鸣」参赛作品 · 交互原型见 `prototypes/debate-room-prototype.html`

> **v0.7 变更（2026-09-14，质询轮收口）**
>
> - 提问方在收到回答后只可「接受回答」并提前结束，或继续追问；不再提供「指出回避」。
> - 每方最多提出 2 问（首次质询 + 1 次追问）。第 2 问被回答后由系统自动推进，不再等待提问方确认。
> - 「接受」只表示结束本轮，不代表同意对方立场，也不产生 MP。回答是否回避由终局 AI 对照完整问答 transcript，在「回应」维度评分并引用依据；不由对手人工裁决。
> - 本条取代此前「接受 / 继续追问 / 指出回避」三选一及对局报告中的人工回避记录。

> **v0.6 变更（2026-09-13，撮合重设计）**
>
> - **变更动因**：打分撮合把"立场对立"当成要算法去算的东西，但用户自己选边就能 100% 保证对立——把撮合从算法问题简化成选边问题。争议地图管线已在产出论点对（27 议题 / 37 论点），预设正反方论点的原料是现成的；同时六维结构画像每局必产，正好接替 base/debate/style 成为撮合信号，形成「对局 → 画像 → 更准的撮合」闭环。
> - **本次改动**：**撮合改为选边制**——① 系统按议题给出预设论点对（正方论点 / 反方论点，来自争议地图）；② 用户**选边**（可以选自己不信的一边，这是辩论训练特性）；③ 撮合**真人优先**（守另一边的候选，按六维画像相近度排序），**Bot 兜底**（持预设对方论点开局）。原 `base × 0.35 + debate × 0.45 + style × 0.20` 公式退役；**D2（style 是否取知乎收藏/关注）随之作废**，OAuth 安心留在阶段 5。

> - **本条作废**：v0.5 及之前"匹配（立场对撞）按分数撮合"的表述；卡 1-5 的旧公式；D2 的存在意义。
> - **红线注记**：**预设论点只是立论的起点，不替代立论**——用户仍须自己填写立论结构、自己说话；选边是选择"守哪个论点"，不是选择"抄哪段话"。

> **v0.5 变更（2026-09-13，一条减法）**
>
> - **变更动因**：概念对齐作为独立前置阶段，本质是让双方先"谈好怎么打"再开打——这在竞技辩论里是先手优势、在审议里是仪式成本，都不是用户要的。定义不该被前置程序裁决，它本身就是可以交锋的东西。

## 0. 一句话

辩论间不是线上辩论赛，也不是评论区，而是一个**将观点、证据和反驳结构化的公共推理空间**——围绕一个知乎问题临时开间，让观点不同的人在**规定轮次**里把分歧谈清楚，散场时留下一份可复盘的对局记录。

**本模块不依赖辩论树**：不预提交树、不写回树、不点选树节点。对局产物是自洽的「对局报告」。

## 1. 最终流程（单一模式，约 20 分钟）

```
选边（预设论点对）→ 撮合（真人优先 · Bot 兜底）→ 就绪
  ① 立论          填「立论结构」（可选关键定义 + 核心结论 + 1-2 条理由 + 可选依据）
                    → 开篇陈述（定义→结论→理由→证据→判断标准），
                    Host 结构提示不代写
  ② 质询轮        一问一答 ×2（双方各一次提问权）：
                    提问方选对方**立论结构里的条目**（含关键定义）→ 选问题类型 → 提一个问题
                    回答方回答 → 提问方接受并提前结束，或继续追问（限 1 次）
                    追问被回答后自动进入下一轮；是否回避由终局 AI 评分
  ③ 自由对辩      各 1 次发言，必须标注类型：反驳 / 举证 / 承认 / 修正 / 寻共识
  ④ 结辩          比较双方立论与质询结果，做结构化收束（不要求承认对方观点）
  ⑤ 终局          对局报告（质询记录 / 共识 / 分歧 / 未决 / 修正 / 定义分歧）
                  + 六维结构画像（不排名）
                  + 段位结算（鸣声值明细）
                  → 轮次到此结束，对局完成
```

**撮合：选边制（v0.6）**

| 步骤 | 说明 |
|---|---|
| 论点对 | 系统按议题给出预设正反方论点（来自争议地图管线），每边 1 条核心论点 + 立场标签 |
| 议题门禁 | 只有含“是否 / 会不会 / 能否 / 该不该 / 值不值得 / ……吗 / 还是……”等明确站队结构的题干可进入辩论间；只问“为何 / 什么 / 如何 / 多大 / 多久”的开放解释题保留在争议地图，但不参与撮合 |
| 选边 | 用户浏览后**选一边**；选自己不信的一边完全允许（竞技辩论式训练） |
| 对手 | **真人优先**：守另一边的候选，按**六维画像相近度**排序（见下）；**Bot 兜底**：候选池空或超时，Bot 持预设对方论点开局 |
| 排序信号 | 双方六维结构画像（历史对局产出）的**水平相近度**：`score = 1 − mean(|dim_i − dim_i'|)/100`——避免碾压局与被碾压局；分数并列随机 |
| 冷启动 | 新用户无画像 → 候选池内随机；池空 → Bot。**无需任何历史数据即可开局** |
| 可解释 | 撮合理由可展示：「同一场论点对、你守正方；对方画像与你相近（逻辑 82/回应 78）」 |

**流程设计的三条原则**：① **每个阶段有唯一使命**，消灭「面对空白输入框不知道说什么」；② **结构先行，定义靠打出来**——立论结构在开打前给质询提供靶子；关键定义不前置协商，谁的定义站不站得住，在质询里见分晓；③ **修正是一等公民**——好的辩论不是死守立场，而是让观点变准确。

## 2. 定义的处理（不设独立对齐阶段）

- **定义不是前置协议，是可被质疑的论点**。双方在立论中自然给出自己使用的关键定义（可选字段），随立论陈述公布。
- 对方在 ②质询轮可以**直接选中「关键定义」条目发问**（如：「你说的『窗口期』是客观机制还是主观感受？」）；自由对辩中也可用「反驳 / 修正 / 寻共识」处理定义分歧。
- 定义分歧**不由 Host 拦截、不要求重选、不阻塞流程**——分歧本身记入对局报告（「定义分歧」条目），这比强行对齐更诚实：它告诉读者"这场架是在哪两个定义之间打的"。
- Host 在立论阶段的结构提示可包含定义提示（如"你的结论依赖一个未言明的定义"）——**提示即止**。

## 3. 立论结构（①）

立论不写自由长文，先填三个字段。**这是本条发言的骨架，不是一棵树**：不建节点、不上共享画板、不产生跨发言的父子关系。

| 字段 | 说明 |
|---|---|
| 关键定义 | 可选：本方使用的 1 个关键词的界定（如「窗口期＝…」）；**②质询轮可被选中发问** |
| 核心结论 | 默认预填立场表述，可改 |
| 理由 1 / 2 | 支撑结论的理由（至少 1 条） |
| 依据 | 可选，随理由提交，进入证据七档流程 |

- 结构的作用只有一个：**让 ②质询轮有稳定的定位锚点**——提问方按条目（定义 / 结论 / 理由1 / 理由2 / 依据）发起，不需要翻聊天记录。
- 双方**各自填写、互不可见**（对方只在你立论陈述后听到内容）。
- 立论本身仍是一段口语化陈述。Host 在立论阶段做结构提示：观点与证据是否对应、是否把相关当因果、是否有未证明前提——**提示即止，不代写、不评判**。

> 若后续要更简（立论改为纯自由文本、质询按话轮定位），只需删掉本节的字段约束与 ③ 的「选条目」动作，流程不变。

## 4. 发言类型（③④）

自由对辩与结辩的每条发言必须标注类型：

| 类型 | 语义 | 作用 |
|---|---|---|
| 反驳 | 指向对方某条立论/发言提出反对 | 进「分歧」，与被反驳条目关联 |
| 举证 | 补充事实性证据 | 作为证据进七档状态 |
| 承认 | 接受对方某条论证有道理 | **仅作语义标注**，进对局报告「已被承认的论证」栏；不影响任何结算，对方也无法据此得分 |
| 修正 | 修改本方先前论点表述 | 原表述打「已修正」标记 + 新表述，历史可见 |
| 寻共识 | 提出双方可能都接受的表述 | 生成共识候选，进对局报告 |

限制：自由对辩每方 1 次，防刷屏；类型不允许选「攻击/嘲讽」（不存在该选项）。

> **与 v0.3 的差别**：类型不再「驱动自动建边」（那依赖辩论树），只做标注与归档。

## 5. 证据七档状态（贯穿①②③）

每条事实性主张的依据被标记为以下状态之一，随发言一起展示、一起被质询：

```
已提供来源 ｜ 来源可信但不支持结论 ｜ 来源存在争议
缺少证据 ｜ 个人经验 ｜ 价值判断 ｜ 无法验证
```

- 提交依据时用户自报状态；质询中对方可以质疑状态（「你标『已提供来源』，但来源在哪？」）。

## 6. 评审：六维结构画像（⑤）

**不判胜负。** AI 中立评估输出的是**结构质量反馈**（像教练复盘，不像裁判打分）：不排名、不定胜负、不展示「谁赢」。设此边界的原因：LLM 评判有系统性偏差（偏流畅表达、偏模型自身立场）；胜负判定会吸引辩论赛型用户、劝退真分歧用户。

**a. AI 中立评估（六维评分 + 总结）**

中立角色接入终局，依据场上**可观测行为**（发言记录 transcript、证据提交、质询结果、规范表现）生成评估。每个维度单独打分（0-100）并给出具体评分依据，输出综合得分与整体评价；总结用语保持客观中立，终局卡明示「不构成胜负判定」。

| # | 维度（雷达标签） | 评估标准 | 权重 |
|---|---|---|---|
| ① | 立论（立论） | 观点是否明确，论点是否紧扣辩题，判断标准是否合理 | 1/6 |
| ② | 论据（论据） | 证据是否真实、相关、充分，数据来源是否可靠 | 1/6 |
| ③ | 逻辑（逻辑） | 论点与论据是否匹配，推理是否完整，有无偷换概念、因果倒置 | 1/6 |
| ④ | 回应（回应） | 是否准确理解对方观点，是否回应核心攻击，反驳是否有效 | 1/6 |
| ⑤ | 表达（表达） | 语言是否清楚，结构是否连贯，时间分配是否合理 | 1/6 |
| ⑥ | 规范（规范） | 是否尊重对手；有无人身攻击、打断、捏造事实、回避问题 | 1/6 |

综合得分 = **六维等权平均**（权重可后续按运营数据调整）。雷达图为**六维**双方对比展示，标签统一 2 字。

> **口径修正（v0.4）**：v0.3 的流程图与 MVP 清单曾误写「5 维」。正文、Host 接口与测试基线**均为六维**，本版统一按六维表述。

**b. 结果不由对方决定**

v0.3 的「对手承认 / 终局互认」已**废除**（见文首变更块）。本版明确：

- 对局结果**不由对方授予**，也不由 AI 排名决定——它是一份**结构画像 + 客观记录**，没有胜负字段。
- 全局禁止出现 `winner` / `rank` / `胜负` / `赢了` / `败` 等字段与文案。

实现说明：原型阶段为启发式规则（结构完备度、问答轮次、修正行为等映射到分数）；接入 LLM 后由同一接口 `evaluate() → {dims[6], total, verdict}` 返回。模型须把质询问题与对应回答成对比较，在「回应」维度判断是否触及问题，并从 transcript 引用具体发言作为依据。

## 7. 段位系统（鸣声值）

段位衡量**参与质量与信誉**，不衡量对错。数值单位：鸣声值（MP）。

| 获得途径 | MP |
|---|---|
| 完成一场完整对局 | +10 |
| **中途离席 / 超时未应** | **-5** |

「接受回答」只用于结束质询，不参与 MP 或六维画像计算；否则提问方的流程选择会变成对回答质量的隐性裁决。

| 段位 | 门槛 | 隐喻 |
|---|---|---|
| 启鸣 | 0 | 开口的第一声 |
| 锋鸣 | 30 | 锋芒初露 |
| 争鸣 | 80 | 产品同名段，中坚 |
| 共鸣 | 180 | 能听进对方 |
| 和鸣 | 350 | 和而不同，最高段 |

- 段位徽章展示在席位卡与个人主页；高段位用户在匹配中享有「先手权让渡」荣誉（可选）。
- 防刷：同一对手 24 小时内重复对局 MP 减半；离席惩罚不可被重开抵消。

## 8. 对局报告（⑥ 的产物）

对局结束后自动生成、可传播：

```
辩题与双方关键定义（如有；定义分歧显式记录） ｜ 双方立论结构（定义 / 结论 / 理由 / 依据）
质询记录（含提问、追问、回答与接受/自动结束原因） ｜ 关键证据（含七档状态）
已达成共识（标「寻共识」的发言） ｜ 已被承认的论证（标「承认」的发言）
尚未解决的问题 ｜ 观点修正记录（修正前后对照）
六维结构画像对比 ｜ 六维评估总结
```

- 报告落在**房间**上，不写任何外部容器（辩论树集成见 §12）。
- 终局卡可随时退出：点 ✕ 或遮罩空白关闭，回到辩论间回看本场记录；输入区提供「查看对局报告」重开入口与「再来一局」快捷重置。

## 9. 与知乎的结合

围绕知乎问题开临时辩论间：问题 → 回答摘要 → **立场抽取产出预设论点对（选边制的原料）** → 用户选边入席；没有把握的事实性问题，引导「去知乎找证据」；对局报告可沉淀为该问题下的新形态回答。**知乎供给议题、证据与论点对；争鸣把「选了相反一边的人」连接起来。**

## 10. 反模式与边界

| 反模式 | 对策 |
|---|---|
| AI 打分排名 | 永不做——结构画像无名次、无胜负字段 |
| 结果由对方「授予」 | 永不做——结果是一份记录，不是一枚奖章（v0.4） |
| 概念对齐变成抬杠 | **已随阶段删除**：定义不前置协商，改为可被质询的条目 |
| 立论结构代写 | Host 只做结构提示；立论文本必须用户自己输入 |
| 质询变审讯 | 继续追问限 1 次；达到次数后系统自动推进，不允许对手无限追问 |
| 修正被滥用洗白立场 | 修正保留原表述痕迹，报告里可见修正前后 |
| 离席弃局 | MP -5；对局报告标记「未完成局」 |
| 偷换话术 | 完整保留问答 transcript，由终局 AI 在「回应」维度引用原文评价 |

## 11. MVP 范围与验收

**本期交付**：①–⑤ 全流程 P0（原型中证据状态为自报、Host 为选项匹配模拟）。

**验收清单**

- [ ] 开局前出现**预设论点对**，用户可**选边**（允许选对方阵营的论点）；选边结果进入房间状态
- [ ] 撮合真人优先：守另一边的候选按**六维画像相近度**排序，撮合理由可解释；池空/超时 **Bot 兜底**开局
- [ ] **预设论点只预填立论结构的草稿**，用户可改可弃；不能跳过立论直接开打
- [ ] 无独立定义对齐阶段；立论可选填关键定义，**未填不阻塞**
- [ ] 质询轮可选中对方「关键定义」条目发问；定义分歧记入对局报告
- [ ] 双方各自填写立论结构，**互不可见**；立论陈述可被质询定位到条目
- [ ] 质询一问一答；提问方可接受并提前结束，或追问 1 次；达到 2 问后自动推进
- [ ] 自由对辩/结辩发言带类型标注，「修正」保留原表述痕迹
- [ ] 结辩**不要求**承认对方观点，仅做比较与收束
- [ ] 雷达图 **6 维**渲染、无排名
- [ ] 段位结算展示 MP 明细与段位进度
- [ ] 轮次结束即生成对局报告，**无轮次之外的额外交互阶段**
- [ ] 全程无胜负判定、无评判式文案；全局搜 `winner|rank|胜负|赢了|败` 0 命中（`rankCandidates` 为 v0.6 撮合排序纯函数名，不属胜负字段）

## 12. 暂不纳入：辩论树集成

以下为 v0.3 曾有、v0.4 主动移出的能力。**「先不引入」不等于永久放弃**，集中记在此处，避免将来重新引入时漏改。

| 能力 | v0.3 的做法 | 重新引入的前置条件 |
|---|---|---|
| 论证树预提交 | 双方 mini 树挂到共享画板 root 两侧 | 辩论树 `settlement` / 树 schema 冻结（卡 2-1） |
| 发言自动建边 | 发言类型直接生成 con 桶节点与连线 | 同上；且需统一 `web/src/types/graph.ts` 与树 PRD 的节点命名 |
| 终局一键上树 | 对局产物写成挂 root 的 `settlement` 节点 | 同上 |
| 终局互认 | 各方选对方 1 条「我承认有道理」，打金点 | **不建议恢复**：与「结果不由对方决定」冲突 |

> 重新引入时的顺序：**先冻结树 schema → 再让辩论间消费 → 最后改原型与测试**。不要反过来。
