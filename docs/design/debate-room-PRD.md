# 辩论间 PRD（v0.3 · 结构化对局）

版本 v0.3（定稿流程） · 2026-09-11 · 隶属「争鸣」参赛作品 · 交互原型见同目录 `debate-room-prototype.html` · 上游：`debate-tree-PRD.md`

> v0.3 变更：吸收「结构化推理空间」提案——新增概念对齐、论证树预提交、质询轮（一问一答）、发言类型标注、修正标记；评审机制从「打分胜负」改为「结构画像 + 对手承认」；新增段位系统。**单一模式，不设快速/完整双轨。**

---

## 0. 一句话

辩论间不是线上辩论赛，也不是评论区，而是一个**将观点、证据、反驳和共识结构化的公共推理空间**——围绕一个知乎问题临时开间，把回答转成观点节点，让观点不同的人在结构化流程里把分歧谈清楚，散场时留下一张可复盘的论证网络。

## 1. 最终流程（单一模式，约 20 分钟）

```
匹配（立场对撞）→ 就绪
  ① 概念对齐      双方各选 2 个关键概念的定义；不一致 → Host 提示并要求重选
  ② 论证树预提交   各自填 mini 论证树（核心结论 + 1-2 条理由 + 可选依据）→ 上树
  ③ 立论          基于预提交树做开篇陈述（结论→理由→证据→判断标准），Host 结构提示不代写
  ④ 质询轮        一问一答 ×2（双方各一次提问权）：
                    提问方选对方论点节点 → 选问题类型 → 提一个问题
                    回答方正面回答 → 提问方三选一：接受 / 继续追问(限1次) / 指出回避
                    「指出回避」记入争议档案
  ⑤ 自由对辩      各 1 次发言，必须标注类型：反驳 / 举证 / 承认 / 修正 / 寻共识
  ⑥ 结辩          必须先标注「对方最有力的观点」并回应它；允许打 1 次「修正」标记
  ⑦ 终局          争议档案（共识/分歧/未决/最强论点）
                  + 互认环节：各选对方 1 条「我承认有道理」的论点
                  + 结构画像雷达图（5 维，不排名）
                  + 段位结算（鸣声值明细）
                  + 一键沉淀到辩论树
```

**流程设计的三条原则**：①每个阶段有唯一使命，消灭「面对空白输入框不知道说什么」；②承认强度递减——概念对齐和预提交在开打前完成理解，质询轮的「接受/指出回避」就是轻量承认，终局互认是承认的完成态；③修正与承认是一等公民——好的辩论不是死守立场，而是让观点变准确。

## 2. 概念对齐（①）

- Host（LLM）从议题与双方立场声明中抽 2-3 个关键概念（如「高风险」「窗口期」）。
- 每个概念给 3 个定义选项：1 个中性定义 + 2 个带倾向的定义。
- 双方定义不一致时：Host 高亮提示「你们的分歧可能来自对 X 的定义不同」，要求重选；连续 2 次不一致允许带差异继续（记录进档案）。
- 产出：`definitions` 挂在树 root 上，后续所有发言共享这套定义。

## 3. 论证树预提交（②）

| 字段 | 说明 |
|---|---|
| 核心结论 | 默认预填立场表述，可改 |
| 理由 1/2 | 支撑结论的理由（至少 1 条） |
| 依据 | 可选，随理由提交，进入证据核验流程 |

- 双方提交后，两棵 mini 树挂到共享画板 root 两侧——**之后的质询是「指着结构打」**：提问方点选对方树上任意节点发起，不需要翻聊天记录。
- 预提交在开打前完成，也是异步可行的环节（对方未上线时可先提交）。

## 4. 发言类型（⑤）

自由对辩与结辩的每条发言必须标注类型，页面据此自动构建论证关系：

| 类型 | 语义 | 树上行为 |
|---|---|---|
| 反驳 | 指向对方某论点提出反对 | con 桶新节点，与目标连线 |
| 举证 | 补充事实性证据 | 挂为目标节点的依据 |
| 承认 | 接受对方某论点有道理 | 目标节点打「已承认」标记 |
| 修正 | 修改本方先前论点表述 | 原节点打「已修正」标记 + 新节点 |
| 寻共识 | 提出双方可能都接受的表述 | 生成共识候选，进终局档案 |

限制：自由对辩每方 1 次，防刷屏；类型不允许选「攻击/嘲讽」（不存在该选项）。

## 5. 证据七档状态（贯穿③⑤）

每条事实性主张的依据被标记为以下状态之一，随论点一起展示、一起被质询：

```
已提供来源 ｜ 来源可信但不支持结论 ｜ 来源存在争议
缺少证据 ｜ 个人经验 ｜ 价值判断 ｜ 无法验证
```

- 提交依据时用户自报状态；质询中对方可以质疑状态（「你标『已提供来源』，但来源在哪？」）。
- Host 在立论阶段做结构提示：观点与证据是否对应、是否把相关当因果、是否有未证明前提——**提示即止，不代写、不评判**。

## 6. 评审：AI 中立评估 + 对手承认（⑦）

**不判胜负。** AI 中立评估输出的是**结构质量反馈**（像教练复盘，不像裁判打分）：不排名、不定胜负、不展示「谁赢」。设此边界的原因：LLM 评判有系统性偏差（偏流畅表达、偏模型自身立场）；胜负判定会吸引辩论赛型用户、劝退真分歧用户。

**a. AI 中立评估（六维评分 + 总结）**

中立角色接入终局，依据场上**可观测行为**（发言记录 transcript、证据提交、质询结果、规范表现）生成评估。每个维度单独打分（0-100）并给出具体评分依据，输出综合得分与整体评价；总结用语保持客观中立，终局卡明示「不构成胜负判定」。

| # | 维度（雷达标签） | 评估标准 | 权重 |
|---|---|---|---|
| ① | 立论（立论） | 观点是否明确，论点是否紧扣辩题，判断标准是否合理 | 1/6 |
| ② | 论据（论据） | 证据是否真实、相关、充分，数据来源是否可靠 | 1/6 |
| ③ | 逻辑（逻辑） | 论点与论据是否匹配，推理是否完整，有无偷换概念、因果倒置 | 1/6 |
| ④ | 回应（回应） | 是否准确理解对方观点，是否回应核心攻击，反驳是否有效 | 1/6 |
| ⑤ | 表达（表达） | 语言是否清楚，结构是否连贯，时间分配是否合理 | 1/6 |
| ⑥ | 规范（规范） | 是否尊重对手；有无人身攻击、打断、捏造事实、回避问题 | 1/6 |

综合得分 = 六维等权平均（权重可后续按运营数据调整）。雷达图为六维双方对比展示，标签统一 2 字。

实现说明：原型阶段为启发式规则（结构完备度、被接受次数、回避记录、修正行为等映射到分数）；接入 LLM 后由同一接口 `evaluate() → {dims[6], total, verdict}` 返回，评分依据由模型从 transcript 引用具体发言生成。

**b. 对手承认（终局互认）**

- 终局时**每方必须**从对方论点中选 1 条标注「我承认有道理」。
- 被承认的论点在树上打金点标记——**胜利由对手亲口承认，而不是算法评定**。
- 双方可额外互授单项荣誉：「最强证据」「最佳修正」（各限一条）。

## 7. 段位系统（鸣声值）

段位衡量**参与质量与信誉**，不衡量对错。数值单位：鸣声值（MP）。

| 获得途径 | MP |
|---|---|
| 完成一场完整对局 | +10 |
| 概念对齐达成一致 | +2 |
| 每条被对手承认的论点 | +3 |
| 获对手授予荣誉（最强证据/最佳修正） | +5 |
| 质询回答被对方「接受」 | +2 |
| **中途离席 / 超时未应** | **-5** |

| 段位 | 门槛 | 隐喻 |
|---|---|---|
| 启鸣 | 0 | 开口的第一声 |
| 锋鸣 | 30 | 锋芒初露 |
| 争鸣 | 80 | 产品同名段，中坚 |
| 共鸣 | 180 | 能听进对方 |
| 和鸣 | 350 | 和而不同，最高段 |

- 段位徽章展示在席位卡与个人主页；高段位用户在匹配中享有「先手权让渡」荣誉（可选）。
- 防刷：同一对手 24 小时内重复对局 MP 减半；离席惩罚不可被重开抵消。

## 8. 辩论结束后的产物：争议档案

自动生成、可传播、挂在树 root 下的 settlement 节点：

```
辩题与双方定义 ｜ 双方核心论点（预提交树）
论证关系图 ｜ 关键证据（含七档状态）
已达成共识（含「承认」标记的论点）
尚未解决的问题 ｜ 「指出回避」记录
双方最强论点 ｜ 观点修正记录
AI 中立总结 ｜ 结构画像对比
```

终局卡可随时退出：点 ✕ 或遮罩空白关闭，回到辩论间回看本场记录；输入区提供「查看对局报告」重开入口与「再来一局」快捷重置。

## 9. 与知乎的结合

围绕知乎问题开临时辩论间：问题 → 回答摘要 → 立场抽取 → 邀请观点对撞且知识背景匹配的用户入席；树上未回应的追问回流知乎（「去知乎找证据」）；争议档案沉淀后成为该问题下的新形态回答。**知乎供给议题、证据与人；争鸣把「人和对立观点的人」连接起来。**

## 10. 反模式与边界

| 反模式 | 对策 |
|---|---|
| AI 打分排名 | 永不做——结构画像无名次；荣誉由对手授予 |
| 概念对齐变成抬杠 | 定义库由 Host 生成；重选上限 2 次 |
| 预提交树代写 | Host 只做结构提示；立论文本必须用户自己输入 |
| 质询变审讯 | 继续追问限 1 次；「指出回避」记录在案但不变相扣分 |
| 修正被滥用洗白立场 | 修正保留原节点痕迹，档案里可见修正前后 |
| 离席弃局 | MP -5；争议档案标记「未完成局」 |
| 偷换话术 | 质询「指出回避」+ 档案记录（描述式，非指控式） |

**验收清单**

- [ ] 终局互认至少各 1 条；雷达图 5 维渲染、无排名
- [ ] 段位结算展示 MP 明细与段位进度

## 12. 原型说明

`debate-room-prototype.html`：知乎风（无描边盒子、内缩分割线），对手为脚本 Bot，Host 校验用选项匹配模拟 LLM。雷达图为 SVG 手绘，段位结算为本地演示数据。不含真实网络通信。
