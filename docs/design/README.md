# 争鸣 · 总纲（产品全景与文档索引）

版本 v0.1 · 2026-09-10 · 知乎黑客松「灵魂匹配局：社区连接与兴趣社交」参赛作品

---

## 0. 一句话

**争鸣（Dissensus）**：在知乎的问题社区上，用「辩论」替代「点赞」作为连接方式——把观点不同的人撮合到一起，用硬规则保证交锋质量，把每一次交锋沉淀为社区公共资产。

## 1. 核心洞察

1. **知乎的组织原子是问题，不是兴趣圈**。人们因一个具体问题聚集，观点天然分化——这是现成的辩论撮合池，但知乎没有消费「分歧」的场所，分歧只沉淀为对线。
2. **对立面才是最高质量的社交对象**。和观点相同的人聊天是回音室；和观点相反但表达相容的人交锋，才既有信息增量又有连接感。
3. **对线之所以低质，是因为没有规则**。没有「先理解对方」的强制、没有仲裁者的克制、没有沉淀结构——争鸣用产品机制补齐这三件事。

## 2. 产品全景：一个底座，四种体验

**两图分工（历史注记）**：力导向图原管**议题内部**（正反两军怎么布阵、证据多厚、反驳打在哪），争议地图管**议题之间**（哪些主张横跨多个议题、哪里在跨议题地冲突）。判别准则：**若两张图节点与边完全相同、只有排布算法不同，就是同一个可视化**——所以争议地图引入了树物理上无法承载的 `cluster` 多父节点与 `bridge`/`rebuts` 跨议题边。**D3 拍板后力导向图已下线**：争议地图同时承担两层感知，单议题内部展开交给辩论树。

## 3. 四条产品红线（贯穿所有模块）

1. **先承认，再推进**——产品原则（**D6 已拍板**：辩论间不设强制复述闸门）：理解对方是推进讨论的前提，理解偏差由 Host 质询自然澄清，不做拦截式校验。
2. **追问权替代验证权**——Agent 永远只追问、不裁判。禁用词族：「错误 / 谬误 / 输赢 / 对错」。体检输出的是追问点，不是判决书。
3. **模拟与事实永远分离**——事件推演沉浸式隔离：原作（canon）**不注入模型、不展示界面**（调用隔离是天然属性），关键词黑名单兜底；玩家路径标「架空推演」、原作标「史实」，两者永不出现在同一张卡里；终局可选揭示。
4. **不判输赢**——所有模块的产出是共识点、分歧点、追问清单，没有胜负。

## 4. 数据底座（已实证，见 `docs/research/zhihu-post-taxonomy.md`）

- **句式即分类信号**：13 类正则分类命中率 90%+；「该不该 / 值得吗」是甜区。
- **立场均衡度决定可辩性**：条件依赖型 ≈ 哲学辨析型 > 价值表态型（最大簇占比 > 70% 判失衡）。
- **LLM 立场抽取必须两步法**：先归纳立场轴，再逐条归入；单步直判会标签碎片化。
- 知乎 CLI 接口额度与坑位已摸清（实名后搜索 5000/日；30001 错误码要用 quota 区分）。

## 5. 演示路线（现场 5 分钟）

1. **图谱**（30s）：展示 21 个真实议题、五个聚类的关系网络——「选题不是拍脑袋，是数据筛出来的」。
2. **辩论间**（2min）：开一局，走完五阶段——立论（含可选关键定义）→ 质询（可直接质询对方定义）→ 自由对辩 → 结辩 → **对局报告**。
3. **辩论树**（1min）：回到树，展示刚才的发言已挂入对应立场桶，点开 Agent 追问建议。
4. **事件推演**（1.5min）：**扮演历史事件中的一个角色**，外部事件按历史时间表到来，你逐幕做决定、看后果与代价账本（无成败），终局出结局叙述与可选的「历史上实际发生了什么」。
5. 收尾：所有分歧点都回流辩论树——「社区里最吵的地方，变成了最有营养的地方」。
