# 辩论树 PRD

版本 v0.1（设计稿） · 2026-09-09 · 隶属「争鸣」参赛作品 · 交互原型见 `prototypes/debate-tree-prototype.html`

---

## 0. 一句话

把一场辩论的论点、证据、追问组织成一棵**可生长的树**——任何人可以从任意节点继续辩论，Agent 作为追问催化者挂在树上，而不是坐在裁判席上。

## 1. 背景与问题

「争鸣」当前形态是 1v1 异步辩论。它有三个结构性问题：

1. **论点随聊天流走**。一场辩论结束后，观点散落在时间线里，无法沉淀为结构。
2. **只能从头加入**。围观者想回应某个中间论点，只能另开回复，上下文断裂。
3. **Agent 无处安放**。实时对话里 Agent 插话会打断节奏；不插话又没有存在感。

Kialo 已经验证了树状论证地图（claim tree）能让上百人异步协作同一场辩论：根主张在左，pro/con 向右分叉，每个节点独立投票。我们的差异点在于三件事：**Agent 只追问不裁判**、**节点带立场均衡度**、**与知乎真实问题打通（溯源）**。

## 2. 目标与非目标

**目标**

- G1 辩论结构可视化：哪里一致、哪里分叉、哪里没被回应，一眼看清。
- G2 异步参与：任何人可从树的任意节点加入，不需要从头读起。
- G3 Agent 追问点：Agent 标记"未被回应的断言"并给出追问方向，用户一键以建议追问。
- G4 产出公共物：辩论树本身是长期存在的公共资产（知乎长尾属性）。

**非目标（本期不做）**

- 实时辩论间（v0.2，单独 PRD）
- 事件走向模拟（v0.3 事件推演，复用同一树模型）
- **判定任何论点对错（永不做）**——这是产品合法性底线。

## 3. 概念模型

### 3.1 节点类型（3 种）

| 类型 | 说明 | 可投票 | 可挂子节点 | 样式 |
|---|---|---|---|---|
| `root` 根主张 | 议题本身，全树唯一 | 是 | 是（自动归三派） | 蓝底白字 |
| `claim` 论点 | 支持/反对/看条件 | 是 | 是 | 蓝 / 黑 / 灰 |
| `question` 追问 | 指向具体内容的追问 | **否** | 是（回应挂其下） | 虚线 |

> **设计决策：证据不设独立节点。** 一个人回应时应当直接给出证据——依据是 `claim` 的内联字段（`evidence`），随论点一起发布、一起展示、一起被追问，而不是拆成下一层节点。理由：① 表达成本更低，回应者"一段话说清主张+依据"比"先发主张再挂证据"自然；② 树的分支只保留真正的**立场分叉**和**追问**，防止"证据链"把树撑爆；③ 依据跟着论点一起被投票，可信度与说服力绑定。

### 3.2 节点 Schema

```jsonc
{
  "id": "n_01h5x",
  "parentId": "root",
  "type": "claim | question",
  "stance": "pro | con | neutral",     // claim 必填，question 继承父节点
  "content": "苏州编制含金量高于县中，职业天花板更高",
  "evidence": "苏州头部校人均教研经费约为县中 3 倍（教育局公开预算）",   // claim 可选内联依据
  "author": "知乎用户_2v8f",
  "createdAt": "2026-09-09T16:00:00+08:00",
  "votes": { "up": 12, "down": 3 },
  "agentHint": "苏州头部校的竞争烈度可能更高，天花板未必更高——这是可以追问的点",
  "answered": null,                    // question 专用：被回应前为 false
  "source": {                          // 可选，知乎溯源
    "url": "https://www.zhihu.com/question/.../answer/...",
    "quote": "…回答摘要（≤200 字）…"
  }
}
```

### 3.3 树的约束

- **深度上限 4 级**（root 为 0 级）。超出时提示"另开分叉议题"，防无限套娃。
- **追问上限**：每个节点下最多 3 条 question。追问必须指向被追问节点的具体内容，禁止纯表态（"我就是不同意"不构成追问，前端拦截）。
- **三派归位**：root 下的第一层固定为「支持 / 反对 / 看条件」三个桶，新建 claim 必须入桶，不允许多派并存（与立场均衡度统计对齐）。

## 4. 功能需求

### F1 树浏览（P0）

- **渐进展开（渐进披露原则）**：初始只显示根节点；点击任一节点才展开它的下一级（一级一跳，不整棵铺开），已展开节点显示「收起」；每个节点（每一级）都可通过悬停快捷键或详情面板添加支持 / 反对子节点。理由：控制信息密度，用户按需下钻，树的生长感来自「点开」这个动作本身。
- **两种交互形态**（同一数据模型与规则）：① 缩进列表版（`prototypes/debate-tree-prototype.html`），适合快速浏览与移动端；② **无限画布版**（`prototypes/debate-tree-canvas.html`），卡片即节点、自由平移缩放、贝塞尔连线，参考辩论地图类产品的空间布局——树自动排版（叶子定序、父节点居中），「适应视图」一键回到全貌。
- 点击节点选中（蓝色描边），右侧详情面板同步。
- 分支折叠状态持久化到 localStorage。

### F2 添加论点（P0）

- 入口一：节点 hover 时浮出「＋支持 ＋反对」微按钮。
- 入口二：选中节点后，右侧面板的「添加支持论点 / 添加反对论点」主按钮。
- 新节点插入后自动展开父分支并选中新节点，光标落入编辑态。
- 在 `question` 下添加回应时，立场自动继承追问的父论点，不可改。

### F3 投票（P0）

- claim / root 可投票（▲/▼），question 不投票；claim 的内联依据随论点一起被投票。
- 投票实时更新顶部统计条：三派占比条 + 最大簇占比读数。
- 统计口径与调研一致：**最大簇占比 > 70% 时，统计条显示"失衡"提示**，引导运营补反方立场卡。

### F4 Agent 追问点（P0，核心差异点）

- **生成时机**：一轮辩论（双方各发言 ≥ 2 次）结束后，Agent 扫描整棵树，对满足以下条件的节点打 `agentHint`：是断言（无论证）、无子回应、与对向节点存在正面冲突。
- **提示形态**：选中该节点时，详情面板顶部出现提示卡：「Agent 追问建议：{agentHint}」+ 按钮「以此追问」。
- **追问生成**：点击后创建 `question` 节点挂在目标下，目标作者收到通知。Agent 的建议文本作为追问的默认草稿，用户可改。
- **姿态红线**：Agent 文案永远描述"这是可以追问的点"，**禁止**输出"你犯了 X 谬误"类评判（与体检 prompt 的追问式改造一致）。

### F5 知乎溯源（P1）

- 由知乎问题自动建局时，根主张带问题链接，第一层 claim 尽量带 `source`（来自 `question answers` 的回答摘要）。
- 节点卡显示"源自知乎回答"角标，点击跳转原文。

### F6 分歧高亮（P1）

- 对向冲突的两个 claim（同一 parent 下 pro/con 且内容相关）之间画高亮连接弧。
- MVP 退化为：详情面板显示"与它冲突的节点"列表，点击跳转。

## 5. 关键流程

### P1 从知乎问题自动建树（冷启动）

```
question recommend --query 甜区关键词
  → question answers 拉 20 条回答摘要
  → LLM 两步法：先归纳 2-4 个立场轴，再逐条归入
  → 自动生成两级树：root → 三派桶 → 代表论点（带 source）
  → Agent 扫描打 agentHint
```

### P2 加入辩论

浏览树 → 点选感兴趣的节点 → 添加支持/反对论点（或追问）→ 树更新 + 统计条刷新。

### P3 追问循环

Agent 标记 → 用户"以此追问" → question 节点生成并通知作者 → 作者回应（question 下挂回应节点）→ `answered = true`，提示卡消失。

## 6. 反模式与边界

| 反模式 | 对策 |
|---|---|
| Agent 判定对错 | 文案模板白名单，禁止出现"错误/谬误/偷换"等评判词 |
| 无限追问抬杠 | 每节点追问 ≤ 3，且必须指向具体内容 |
| 刷票 | 单节点单用户一票，可改向不可叠加 |
| 树爆炸 | 深度 ≤ 4；单节点子节点 ≤ 8，超出提示收敛 |
| 从众收敛 | 新加入者默认按内容排序而非票数排序展示节点（防锚定） |

## 7. MVP 范围与验收

**本期交付**：F1 + F2 + F3 + F4（P0 全量），F5/F6 视进度。

**验收清单**

- [ ] 初始只渲染根节点；点击节点逐级展开下一级，折叠/展开正常
- [ ] 任意节点可添加 pro/con 子节点并投票，统计条实时更新
- [ ] Agent 追问点可标记、可一键生成追问节点，文案无评判词
- [ ] 追问必须指向具体内容，纯表态被拦截
- [ ] 知乎溯源角标可跳转
- [ ] 失衡议题显示"失衡"提示

## 8. 后续路线

- **v0.2 辩论间**：实时对局，辩论树作为对局的共享画板（双方发言实时上树）。
- **v0.3 事件推演**：复用同一树模型，节点类型替换为「事件节点 / 选择节点 / 后果节点」，选择 → 走向分支；历史事实层可挂知乎事件类回答作溯源。
- 树模型（schema + 权限 + 追问规则）三者共享，仅渲染与语义不同——**这是三个功能一个底座**。
