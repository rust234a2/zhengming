# 发现管线试跑报告（pilot-1，2026-09-13）

目的：真实执行一次「词表 → 广搜 → 门禁」漏斗，验证选题管线可行性。

## 试跑范围

| 项 | 值 |
|---|---|
| 域 | AI × 技术职业（1 个） |
| query | 22 条（冲突对式 12 / 判据式 6 / 拼接式 4） |
| 检索 | `search zhihu` count=10，限速 3s，幂等可重跑，共 22 次 |
| 门禁 | 规则带（classify.py 移植）+ 灰带 LLM（生成正反最强理由，7 次调用） |
| 耗时 | 检索 1m35s + 门禁 44s |
| 额度 | search 22/5000，`question_answers` 零消耗 |

## 结果链

```
22 query ──→ 103 条回答命中 ──→ 81 唯一 question（去重率 21.4%）
        ──→ 门禁：规则带 放行13 / 拒绝3 / 灰带65
        ──→ 灰带 LLM：65/65 判可辩（每题附正反最强理由）
        ──→ 终态：放行 78 / 拒绝 3
```

金牌回归：27 个 v1 真实议题 → 规则带 放行 7 / 灰带 20 / **误杀 0**。
旧门禁误杀的两个 rebuts 高价值端点（「为什么别选计算机专业?」「为什么总有人嘴硬说程序员不会被 AI 替代?」）均安全落在灰带，且 LLM 给出了正确的正反理由。**回归通过。**

## 验证成立的设计

1. **冲突对式构造有效**：18/81 题被 ≥2 条 query 命中，且同一道题被正、反两个方向的 query 同时钓起——「为什么总有人嘴硬说程序员不会被 AI 替代?」被 q01(正)/q02(反)/q22 命中；「AI写程序的能力毋庸置疑很强大,为何没有取代程序员,是哪个环节的原因?」被 4 条命中。**检索层预置跨题交集成立**——这是 v1 里全靠事后 LLM 比对高价购买的结构。
2. **生成式门禁可行**：不分类、只问"正反最强理由"，65 题 7 次调用，产出质量可信（样例见 gated.json），可直接作为 `extract-claims.mjs` 的 prompt 先验。
3. **yield 排名可用**：拼接式/冲突对正题最高（7–9 新题/次），为下轮预算分配提供依据。

## 未达预期（诚实记录）

1. **去重率 21.4%，低于预估 40–60%**——预估失误，count=10 下 query 间交集比预想小。
2. **80.2% 的题只有 1 条回答**——再次坐实"广搜必然浅"，深挖层不可省。
3. **启发式立场熵在 140 字 snippet 上全部 <0.5**——单阵营预判为零。结论：预判对垒不能靠短 snippet + 词表启发式，只能靠灰带 LLM 的正反理由（已验证）或深挖后的完整文本。
4. **判据式 query 产出最差（0–2 新题/次）**，「插画师 成本经济 接单 AI」= 0——判据词是书面语，与搜索分词匹配差，需改口语或并入冲突对。
5. **LLM 门禁 65/65 全放行**——本域内几乎都可辩属合理，但也提示 prompt 偏松；其真正价值在正反理由产物而非筛选，跨域扩量时判据要收紧。

## 结论

**方法行得通。** 22 条 query（预算的 0.4%）就捞出 78 个可辩议题，远超一张 15–20 题地图的选题需求；两个核心创新（冲突对式预置交集、生成式门禁）均被真实数据验证。修正上节 5 点后，可直接上 60 query 全量。

## 补充回测：题级 LLM 预判对垒（2026-09-13，结论：否决）

脚本 backtest-opposition.mjs + backtest-opposition.json。27 题 v1 语料，LLM 看回答全文（400 字截断）逐条判立场并判「有无对垒」，标准答案 = claims.json 的 side。

- **题级结果：TP=0 / FN=2 / FP=0 / TN=25**。对无对垒的 25 题判得全对，但两个真有对垒的题（恰为 rebuts 端点）全部漏掉——召回 0。若以此分配深挖预算，地图信息密度最高的节点会被静默砍掉。
- **两个 FN 性质不同（逐例裁决）**：① 「AI写程序…为何没有取代程序员」是真漏——答 3 明确说「说没有取代不符合事实」，与另两答直接冲突，LLM 未识别（400 字截断可能截掉了关键句）；② 「如果人人都可以通过 AI 写代码…」是**标准答案口径问题**——GT 在 claim 级拆出 +1/-1，但两条回答全文同属「收缩但重定义」中间派，claim 级对立 ≠ 全文级对立，v1 的「85% 单阵营」统计混合了两种口径。
- **答级：LLM 全文判定 11/37=30% vs 词表启发式 10/37=27%**——两者都是掷硬币水平。根因：本测试让 LLM 相对「题目隐含的主流担忧方向」判立场，参照系歧义导致系统性错位。v1 两步法先提炼 claim、再相对 claim 判 side，正是为了绕开这个问题；本测试把它简化掉了，所以崩。
- **最终结论：不存在便宜且正确的「预判对垒」**。便宜的方法（启发式 / 题级 LLM）都不准；准的方法（claim 级提炼 + 比对）就是深挖本身的花费。管线决策：不设独立预判步骤，检索层全量照抓（78 次 ≈ 1.6% 额度），「有无对垒」由深挖后的既有 claim 级判定承担；门禁 pro/con 理由仅作 extract-claims 的 prompt 先验，**不作预算闸门**。

## 口径修正（2026-09-13 晚）：弃用「有对垒」二元设定

用户指出：议题的角度是多元的，不只有是非两派。该批评成立，且比「LLM 判不准」更根本：

1. 「有对垒」预设了单一立场轴（正/反/中），但同一议题域下真实并存的论点往往分属不同角度——如本语料中「程序员是否被取代」域下同时存在：隐性经验不可替代 / 长任务中偏离且固执 / 已替代相当一部分（裁员潮）/ 真难点是需求分析 / 岗位重定义而非消失。这些角度之间是**多边关系**（任意两个都可能共鸣或冲突），压成正反两派必然失真。问法本身双面的题（《AI 到底是在提高效率，还是在抢普通人的饭碗?》）连「正方是谁」都无法定义。
2. 因此回测的 TP/FN 混淆矩阵建立在错误假设上——它否决的是「题级二元预判」这个任务设定本身，而非 LLM 的能力。
3. 实证佐证：地图中 rebuts 边最强的端点《为什么总有人嘴硬说程序员不会被 AI 替代?》gtDist=+0/-1/~0（单回答、题内无对垒），其地图价值完全来自跨题关系——题级「对垒」从来不是地图价值的度量。

**管线修订**：① 门禁问法由「正反双方最强理由」改为「能否生成 ≥2 个互不相同的角度/理由」（多视角，非两派）；② 删除立场熵 / 阵营分布等一切题级聚合口径，side 仅作 claim 的局部标注，不做题级统计；③ shortlist 打分 = 可辩性 + 多重命中 + 主体多样性 +（深挖后）主张簇数与跨题边数，「对垒」不作为任何门槛。

## 立场派生实验（2026-09-13 晚，结论：成立）

脚本 derive-polarity.mjs + polarity-report.json。符号谱二分：same-claim=+1 / rebuts=−1（按置信度加权，幂迭代求符号邻接矩阵主特征向量），仅对「含 rebuts 且 ≥3 边」的连通分量二分，其余中性。输入全部为 v1 既有边，零 LLM 调用、纯图算法可复现。

- **数据**：32 条去重跨题边（same-claim 23 / rebuts 9）→ 21 论点入图、15 条无跨题边 → 5 个连通分量。
- **两个极化分量，结构平衡度都是 1.0**：分量1（行业周期三角，3 论点/3 边，λ=1.80）与分量4（技术壁垒八元组，8 论点/16 边，λ=4.19）。balance=1 意味着不存在矛盾环（如 A≈B、B≈C、A 却 ⊥ C）——v1 的两两判定内部自洽，派生出的阵营是真实的。
- **阵营语义符合直觉**：分量1 A={需求萎缩/冲击真实}×2，B={不会消灭只是重定义}；分量4 A={替代有限/价值转向}×7，B={岗位持续收缩悲观}×1。
- **v1 side 一致率仅 0.57–0.67，且错在 v1**：分量1 里「马斯克：毁灭性打击」(v1:positive) 和「别选计算机：需求下降」(v1:negative) 被 same-claim 0.85 直接连着——两条主张同意、v1 却给了对立标签，因为 side 是相对各题隐含主流方向判的（参照系歧义的直接实锤）。符号图按主张实际关系分组，不受题目参照系影响。
- **中性分配合理**：人类特质团（5 论点全 same-claim、无 rebuts）、担责团、教育对、加上 15 条无跨题边论点，共 25/36 中性——不参与冲突的不硬派阵营。
- **已知边界（诚实记录）**：① 阵营是分量局部的，跨分量无对齐——分量1-A（收缩派）与分量4-B（悲观派）语义接近但图上不连通，谱方法给不了全局两翼；若前端 forceX 需要全局朝向，只能用展示层启发式（如已有 cluster.side）定朝向，阵营成员关系仍以图派生为准。② 特征向量符号歧义已用固定规则消除（字母序最小节点归 A），结果确定性可复现。
- **结论**：改法三成立。v2 管线中 polarity 字段由 derive-polarity 派生，extract-claims 的 side 退出分析层；前端着色/forceX 改读派生阵营（展示语义 A/B 待 PRD v0.4 同步）。

## 决策记录：暂不接入 build-map，v2 复评（2026-09-13）

用户决策：符号图派生 polarity 当前只作为验证过的实验产物留在 research/，**暂不接入 build-map.mjs**、不动 PRD。理由：当前 v1 数据下分量1与分量4不连通，全局朝向规则属"为没有的事做设计"，提前定就是过早优化。

**触发复评的明确条件**（满足任一即可）：
1. 分量1与分量4被新跨题边连通（最直接的信号——岛屿合并后全局两翼自然成立）；
2. v2 地图 topic ≥ 30 且 claim ≥ 60（规模足够让派生阵营有意义）；
3. 到 v2 地图构建时点本身（自动重跑 derive-polarity，看分量数变化）。

**过渡期的口径**（与既有口径修正一致，不冲突）：
- extract-claims 的 side 字段**退出分析层口径**——不进 shortlist 打分、不进任何门槛；
- side 仅在 build-map 输出层保留，作前端着色的临时来源（明知有参照系歧义，作为过渡）；
- polarity 派生算法已就位（derive-polarity.mjs + polarity-report.json），随时可接入，接入时 build-map 删除对 LLM side 的依赖、改读派生 polarity。
