# 知乎帖子类型调研：基于句式关键词的分类与辩论适配度评估

> 目的：为「争鸣 Dissensus」的议题库建设提供**可自动化的题型识别规则**，并判定哪些题型适合做成辩论。
> 采集工具：项目内知乎 CLI（`zhihu-cli v0.5.0`，开放平台 Access Secret）
> 采集日期：2026-09-09

---

## 〇、方法与样本说明（先说清楚偏差）

> **【9/9 更新】实名认证后额度放开（搜索 5000 次/日），此前因限流缺失的 16 个关键词已全部补采。本节旧版"未覆盖"说明已过时，保留仅作记录。**

| 项 | 说明 |
|---|---|
| 采集方式 | 24 个句式关键词各搜一次（`count=10`）+ 热榜 30 条 |
| 实际成功 | **24 个关键词全部成功**（9/9 补采 16/16，每次 10 条） |
| 有效样本 | 原始 270 条 → 去重后 **251 条标题** |
| 覆盖关键词 | 全部 24 个 |
| 配额真相 | `30001` 同时表示"限流"与"配额耗尽"，必须用 `quota` 区分；旧额度为试用包（搜索仅 10 次），实名认证后为 5000 次/日 |

**仍须声明的偏差：**

1. **关键词采样是有偏的**——按假设的句式去搜，分布不等于知乎自然分布。
2. **热榜 30 条才是自然样本**。下文把两者分开统计。
3. **「万字 / 深度解析」不是内容类型信号，是深度信号**——补采后两者 20/20 全部落入"其他/未分类"，证实它们应作为正交属性（长文标记）而非独立类型。

## 一、分类体系：13 类（句式关键词 → 类型 → 认知性质 → 可辩性）

按**句式关键词**切一级，再按**宾语性质**做二级校正。规则已落地为 `classify.py`，可复用到真实数据接入。

| 类型 | 识别句式（正则关键词） | 认知性质 | 可辩性档位 | 辩论适配 |
|---|---|---|---|:-:|
| 事实核查 | 是真的吗 / 真的假的 / 辟谣 / 确有其事 | 事实认定 | 排除区 | ✗ |
| 资源聚合 | 有哪些 / 求推荐 / 盘点 / 汇总 / 书单 | 信息列举 | 排除区 | ✗ |
| 实务求助 | 怎么办 / 怎么才能 / 注意什么 / 如何办理 | 操作求解 | 排除区 | ✗ |
| 经验叙事 | 是什么体验 / 什么感受 / 我的…经历 | 个人经历 | 排除区 | ✗ |
| 深度长文 | 万字长文 / 深度解析 / 讲透 | 系统阐述 | 非题源，但**是最好的议题素材** | — |
| 审美评价 | 好看吗 / 好听吗 / 水平如何 | 主观偏好 | 弱可辩 | △ |
| 归因探究 | 为什么 / 为何 / 什么原因 | 因果解释 | 弱可辩 → 可用 | ○ |
| 概念辨析 | 是什么 / 什么叫 / 算不算 / 的定义 | 定义界定 | 可用区 | ○ |
| 比较选择 | 哪个更好 / A 还是 B / 有什么区别 | 权衡取舍 | 可用区 | ○ |
| 观点评价 | 如何评价 / 怎么看 / 如何看待 | 价值 + 论证 | 甜区（高风险） | ◎ |
| 决策抉择 | 该不该 / 要不要 / 值得吗 / 有必要吗 | 价值判断 | **甜区** | ◎ |
| 预测推演 | 会不会 / 能…吗 / 意味着什么 / 产生哪些影响 | 预判 | **甜区** | ◎ |
| 情境假设 | 穿越 / 如果…你会 / 假如你是 / 你会怎么办 | 思想实验 | **甜区** | ◎ |
| 其他/未分类 | — | — | 待人工复核 | ? |

### 二级判定：同一句式，宾语决定能不能吵起来

这是本次调研最关键的一条。**只看句式会误判**，必须看它在问什么：

| 句式 | 宾语性质 | 实际可辩性 |
|---|---|---|
| 为什么 X | X = 自然/科学机制（"发烧为什么发抖"） | **排除**，有标准答案 |
| 为什么 X | X = 他人动机（"他为什么要在镜头前…"） | 弱可辩，纯揣测无证据 |
| 为什么 X | X = 社会现象（"年轻人为什么躺平"） | **可用**，多因一果 |
| 如何评价 X | X = 电影/剧/游戏/人物 | 弱可辩，属审美偏好 |
| 如何评价 X | X = 突发公共事件/政策 | 甜区但**高风险**：事实未定、情绪浓度高 |

## 三、四个关键发现

### 发现 1：热榜不能用来建题库

最适合辩论的「该不该 / 值得吗」在热榜里出现 **0 次**。原因是这类题**个人化、长尾、无时效**，天然不会成为热点。

热榜 30 条里，弱可辩 23.3% + 高风险甜区 10% + 排除区 13.3% = 近一半不可用，且充斥突发公共事件、灾难、名人逝世这类**不适合拿来做辩论**的题材。

> **产品结论**：议题库必须靠**关键词定向检索**挖掘，不能抓热榜。热榜只能用于观察生态，不能用于选题。

### 发现 2：占比最高的「如何评价」不是最佳题源

观点评价占 28.3%（采样）/ 30.0%（热榜），是最大类。但拆开看它内部是分裂的：

- 评价文艺作品 / 人物 → **审美偏好，吵不出东西**
- 评价突发公共事件 / 政策 → **可辩，但事实未定、情绪浓度高、易变站队**

真正干净的甜区在只占 16.3% 的「该不该 / 值得吗」。

### 发现 3：「该不该 / 值得吗」是最干净的甜区入口

它同时满足四条，而这四条是别的题型给不了的：

1. **不涉事实认定** —— 不存在"查一下就知道"的尴尬
2. **不站队公共事件** —— 无政治/时事风险
3. **人人有立场** —— 无专业知识门槛，冷启动容易
4. **理由天然分化** —— 保守 vs 进取、个人 vs 家庭、短期 vs 长期，论证路径互不兼容

而且句式极好识别（`该不该` 正则命中率 10/10），可全自动挖掘。**建议作为 MVP 议题库的主力题型。**

### 发现 4：情境假设类是知乎独有金矿，且此前的分类体系漏掉了它

样例：`穿越成刚毕业的祁同伟，被分到偏远乡镇司法所，你会怎么办？`

这类题的价值在于：无标准答案、必须给出完整推理链、不涉身份政治、趣味性高、参与门槛低。它不属于交接包 `HANDOVER` 里那 14 类内容类型中的任何一类 —— **建议补进分类体系**。

## 四、哪些适合做成辩论（按优先级）

| 优先级 | 题型 | 理由 | 风险 |
|---|---|---|---|
| **P0** | 决策抉择（该不该 / 值得吗） | 无事实争议、人人可答、理由分化 | 低。避免涉及他人隐私的过度具体个案 |
| **P0** | 情境假设（穿越 / 如果我是你） | 推理链完整、趣味高、不涉身份 | 低。避免政治角色扮演 |
| **P1** | 预测推演（会不会 / 意味着什么） | 可证伪，能做"三个月后回看"钩子 | 中。需避开未定事实的突发事件 |
| **P1** | 概念辨析（算不算 / 是什么） | 可辩性高、天然收敛、不依赖外部事实 | 低。被严重低估 |
| **P2** | 社会归因（为什么 + 群体现象） | 多因一果，可辩 | 中。需过滤掉科学机制类 |
| **P3** | 观点评价（如何评价 + 长期现象） | 论证空间大 | **高**。必须剔除突发公共事件 |
| ✗ | 事实核查 / 资源聚合 / 实务求助 / 经验叙事 | 无对立立场 | — |

## 六、对「争鸣」的三条落地建议

1. **议题库采集走关键词定向检索，不走热榜。** 优先级：`该不该` > `值得吗` > `穿越/如果我是你` > `会不会` > `算不算`。每个关键词一次搜索可稳定获得 10 条候选。

2. **在既有 14 类内容分类之外，补一类「情境假设」。** 它不属于任何一种认知性质分类，但辩论适配度最高。

3. **类型错配检测要前置到选题阶段。** 此前 `HANDOVER` 里的洞察 —— 知乎无效争论源于有人答"是什么"、有人答"应不应该" —— 意味着同一个问题下会混入多种类型。产品端应该在**建局时锁定单一类型**，只在同一类型内匹配持不同立场的人，而不是等问题答完了再检测。

4. **配额耗尽会被误判成限流 —— 这是本次最大的一个坑。** `search zhihu` 报 `30001 rate limit exceeded`，字面上是"限流"，等 40 分钟并不恢复。**真实原因是配额用完了**：`quota` 显示 `zhihu_search` 的 TotalQuota 就是 **10**，已用 10、剩余 0。

   佐证：`hot` 只调用 2 次就同样报 30001，而它的 TotalQuota 恰好是 2。说明 **30001 同时用于"配额耗尽"和"QPS 限流"，看错误码无法区分，必须用 `quota` 命令判断。**

   正确做法：任何 `30001` 先跑 `zhihu-cli quota`；`RemainingQuota > 0` 才是真限流（等待即可），`= 0` 是配额见底（等待无用）。

5. **文档额度与实际不符，不要照文档规划。** `references/open-platform.md`（核验于 2026-07-16）写的是「知乎搜索 5000 次/天、热榜 100 次/天」，但本账号实测：搜索 10、热榜 2、直答 2、`question_answers` 10、`creator` 10、`tools` 2、`user_data` 1000、`knowledge` 500。数量级差两三个档次，应是邀测试用包。文档自己也注明"额度和邀测规则可能调整"。

6. **换 Access Secret 救不了。** 文档明确：同一账号下所有 Access Secret **共享同一个额度池**，某能力耗尽后该账号所有 Secret 均无法调用。可申请 20 个 Secret，但对提额无帮助。提额只有一条路：邮件 `openplatform@zhihu.com`，说明场景与预估调用量，1 个工作日回复。

   **额度规划（截至 9/9）：** `user_data` 1000 次与 `knowledge` 500 次几乎未动，是当前唯一能放开用的通道。`user_data` 走 `me` 命令，可读本账号的创作、关注、收藏夹 —— 其中**收藏夹正是「三层信号」方案的核心数据源**，已实测可用（返回真实收藏夹：量化 / 理财 / 论文 / 各种知识）。建议把 demo 数据建立在 `me` 之上，把 `question_answers` 仅剩的几次留给关键假设验证。

## 七、补充实测：`question answers` 接口（可提取问题下的用户回答）

上一版调研只覆盖了「搜索 → 标题」。本节补充**能否拿到问题下面的回答正文**，这是议题库与立场卡的数据基础。

### 7.1 接口能力

CLI 升级到 **0.6.0** 后新增 `question` 命令（`current` 目录可能仍指向 0.5.0，需显式调用 `versions/0.6.0/zhihu-cli.exe`）：

| 命令 | 作用 | 额度 |
|---|---|---|
| `question recommend [--query 主题] --count N` | 按账号画像或指定主题推荐问题，返回标题 + URL | 与下者共享 `question_answers`，默认 **10 次** |
| `question answers --question-url <URL> [--offset N --limit 20]` | 拉取该问题下的回答摘要，可翻页 | 同上 |

返回字段仅 4 个：`ContentType` / `ContentToken` / `Url` / `Summary`。

**关键限制（必须知道）：**

1. **Summary 不是全文**，是服务端摘要或截取文本。实测平均 151 字，最长约 205 字（长度上限约 200 字，超出被截断）。
2. **不含作者、赞同数、评论** —— 拿不到社交信号，也拿不到"谁说的"。想拿这些只能走 `search zhihu`，但那是按关键词召回单条，不是按问题拉取。
3. 要全文只有 `Url`，意味着**必须爬页面**，不在开放平台授权范围内。

### 7.2 实测样本

问题「余生该不该将就婚姻？」（`2037894469836591727`），一次调用拿 **14 条**回答（`IsEnd=true`，该问题答案总量就是 14）。

立场分布（人工判读）：

| 立场 | 条数 | 特征 |
|---|---|---|
| 绝不将就 / 宁可高质量独处 | 9 | 主流，理由集中在"内耗""自我""不必用婚姻定义幸福" |
| 可以将就 / 跟谁过都一样 | 1 | 明确的反方，仅 1 条 |
| 重构问题框架（"没有将就一说"） | 1 | 不答该不该，质疑前提 |
| 叙事型（讲朋友的故事，未明说立场） | 1 | 有内容无立场 |
| 噪声（1 字、12 字） | 2 | 需过滤 |

### 7.3 结论升级：立场均衡度假设已被 4 议题对照验证（9/9 更新）

原假设"句式甜区 ≠ 可辩，需立场均衡度指标"已用 4 个议题实证：

| 议题 | 类型 | 有效/总 | 最大簇占比 | 判定 |
|---|---|---|---|---|
| 余生该不该将就婚姻？ | 价值表态型 | 12/14 | **75%** | 失衡 |
| 43岁县中教师该不该辞职去苏州？ | 条件依赖型 | 15/18 | 53% | 均衡 |
| 国际学校高昂学费值得吗？ | 条件依赖型 | 19/20 | 16%（标签碎） | 均衡 |
| 自由=拥有更多选择还是不需要选择？ | 哲学辨析型 | 14/16 | 36% | 均衡 |

**三条升级后的结论：**

**① 失衡与否跟议题类型强相关，句式完全预判不了。** 四个议题里三个是均衡的，只有"婚姻将就"失衡。浮现出的规律：

- **价值表态型**（婚姻、生育等生活方式站队）→ 容易一边倒，情绪浓度高
- **条件依赖型**（辞职、教育投入，答案依赖个人财务/家庭状况）→ 表面"看条件"，实际天然分裂为"支持/看条件/反对"三派
- **哲学辨析型**（自由的定义）→ 天然分散，6 个立场簇

→ 选题优先级应为：**条件依赖型 ≈ 哲学辨析型 > 价值表态型**。价值表态型不是不能用，而是要靠"少数派立场卡"机制兜底（见②）。

**② 「反方稀缺」本身就是产品机会（维持原结论）。** "能将就就将就吧 跟谁过都一样"这种回答在知乎会被淹没，但它恰恰是辩论里最缺的角色。产品可以显式把少数派立场卡挑出来，作为"你要不要为这个立场辩护"的入口。

**③ 认知类型混杂再次被证实（维持原结论）。** "你对自己定位准确吗"这类回答不答该不该，而是在质疑提问者——问题层面的错配，建局时必须用「同类型内匹配异见者」规则过滤。

**方法论警告：LLM 直判立场标签会碎片化。** 国际学校议题 19 条回答被拆成 17 个标签（16 条只有 1 条）。原因是每个回答的条件差异都被当成了新立场。正确做法是**两步法**：第一步先让 LLM 归纳该议题的 2-4 个立场轴，第二步再把回答逐条归入。单步直判的"均衡"读数不可信（16% 是标签碎片导致的假象，合并后约 10:7，仍属均衡但没那么夸张）。

### 7.4 建库流水线（9/9 实名认证后已可全量运行）

```
question recommend --query "该不该 值得吗"   →  候选问题（10 条/次）
        ↓  按句式筛（classify.py）+ 议题分型（价值表态/条件依赖/哲学辨析）
question answers --question-url <URL>        →  20 条回答摘要/次，可翻页
        ↓  LLM 两步法
        立场轴归纳 → 逐条归入 → 均衡度 = 最大簇占比
        ↓
        立场卡（主张 + 理由 + 认知类型 + 少数派标记）
```

脚本和数据均位于 `research/zhihu-corpus/`：`collect_answers.py`（recommend / answers / pipeline 三模式）、`stance_balance.py`（立场均衡度验证，注意其中单步直判法的碎片化问题）、`refill.py`（关键词补采）。
